# Working in this repo

Novera Interiors: a Laravel 13 / Livewire 4 / Filament 5 site + CMS in English,
Kurdish (Sorani) and Arabic. See `README.md` for the full picture.

## The rule that shapes everything

Nothing on the public site is static. If you find yourself typing a string,
colour, image path or URL segment into a Blade template, it belongs in the
database instead. Check whether it fits an existing home before adding a new
one:

- **Settings** — site-wide scalars (brand, palette, motion switches, SEO).
- **Content collections** — ordered lists (stats, standards, facilities,
  contact rows, socials, filter chips).
- **Sections** — page composition, one row per block.
- **Catalogue models** — concepts, materials, projects, services.
- **Translations** — English copy that appears in a template.

## Conventions

- Headings mark their gold italic fragment with `*asterisks*`. Render them
  with `nv_accent()`, never `{{ }}` — the marker splits the string into the
  fragments the dictionary is keyed by.
- Read translatable model attributes with `nv_tr($model, 'field')`, not
  `$model->field`. It falls back to the source language through the dictionary.
- Build URLs with `nv_url()` / `nv_entity_url()`. There are no named routes for
  public pages; slugs are content.
- Images go through `nv_img($media, $w, $h)` so remote placeholders get the
  crop they need.
- Mark editable copy with `nv_edit('model', $id, 'field')`. Adding a field also
  means adding it to the allowlist in `App\Support\InlineEditor`.

## Adding a page-builder section

The CMS calls them sections; the registry class is still `SectionBlocks`.

1. Entry in `App\Filament\Support\SectionBlocks::definitions()` with `hint`,
   `group` and `icon` — the picker is a grid of cards, so all three are needed.
2. View at `resources/views/site/sections/<type-with-dashes>.blade.php`.

The admin form is derived from the definition. Do not hand-write one.

Mark every wording field with `nv_edit('section', $section->id, 'field')` and
every picture with `nv_media_edit(...)`, or it can only be reached through the
admin form — `EditingFlowsTest` fails if you forget. A field inside an `<a>`
goes in a `<span>` so the link stays a link.

## Writing for the CMS

Editors here are not developers. When you add a field:

- Label it as a sentence someone would say out loud — "Main button goes to",
  not "Primary CTA target". No field may contain the word "key".
- A destination is a picker (`pages`, `forms`, `collection`), never free text.
- Identifiers and sort orders go in `Advanced::section()`, collapsed. `key` is
  generated by `HasAutoKey`, so never make it required.
- New list screens get a `getSubheading()` saying what the screen is for.

`tests/Feature/CmsUsabilityTest.php` enforces most of this, and
`tests/Feature/EditingFlowsTest.php` covers the three flows an editor actually
uses: adding a page, adding a section, and editing on the page.

## Gotchas in the editor

- `$wire.commit` belongs to Livewire's own request machinery — the PHP method
  is `saveInlineEdit` for that reason. Do not rename it back.
- CSS for the panel lives in `resources/views/filament/admin-styles.blade.php`,
  injected by a render hook. A `@push('styles')` inside a component never
  reaches the layout when Livewire renders it into a modal.
- Filament 5 publishes its palette as bare `oklch()` in `--gray-*`. Use
  `var(--gray-200)`, never `rgb(var(--gray-200))`.

## Gotchas

- Don't cache Eloquent models across requests — `Site` memoises per request on
  purpose. Anything longer-lived belongs in `CacheFlusher::WATCHED`.
- Pivot tables follow Laravel's alphabetical convention (`material_project`,
  not `project_material`).
- The public catch-all route excludes `config('novera.reserved_prefixes')`.
  Add any new top-level path there or it will 404 into the page resolver.
- Filament 5 uses `Filament\Schemas\Schema` and unified `Filament\Actions\*`.
  Tables use `->recordActions()` / `->toolbarActions()`.
